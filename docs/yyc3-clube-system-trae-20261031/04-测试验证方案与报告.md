## 四、单元测试覆盖建议与关键校验点

本次已落地 `__tests__/artist-report.test.ts`（7 条）：

| 用例 | 关键断言 |
| --- | --- |
| 日期过滤 | 16 条、全部落在 10-24 ~ 10-31 |
| 组合筛选 | 门店/艺人/状态/搜索各返回正确结果 |
| 扣款指标 | 9 笔有效、总额 790、7 位艺人、平均 87.78 |
| 台费指标 | 22 次、台费 10320、扣款 790、实收 9530、结算率 76.6% |
| 汇总排序 | 8 行、倒序、每行 `实收 = 台费 - 扣款` |
| 扣款过滤 | 迟到 4 条、已扣款状态一致 |
| 格式化 | 金额、时长边界 |

**导出与审计契约**（`__tests__/artist-report-export.test.ts`，8 条）：

| 用例 | 关键断言 |
| --- | --- |
| 报表类型白名单 | 4 类合法值通过，非法值（含 `null`/对象）拒绝 |
| 列定义唯一 | 每类报表列 key 不重复，label 非空 |
| 行数上限 | `MAX_EXPORT_ROWS === 50000` |
| 文件名时区 | `Asia/Shanghai` 跨零点仍生成当日日期 |
| 筛选序列化 | 空白/空串剔除，值做 trim，顺序稳定 |
| 本地日期 | `toArtistExportDate` 不使用 UTC，避免日期前移 |
| CSV 转义 | 逗号/引号/换行正确包裹，引号双写 |
| 空数据 | 仅输出表头，不生成多余空行 |

**审计写入**（`__tests__/artist-report-repository.test.ts`，2 条新增）：`recordExportAudit` 参数顺序与 `filter_json::jsonb` 转换、`operator_trust` 缺省为 `none`、可选字段缺失写 `NULL`。

**导出操作人解析**（`__tests__/export-operator.test.ts`，7 条）：

| 用例 | 关键断言 |
| --- | --- |
| 令牌通过校验 | 返回 `trust=jwt`，`operatorId/operatorName/storeId/role` 与令牌一致 |
| 令牌缺少 name | `operatorName` 回退为 `userId`，仍为 `jwt` |
| 令牌非法/过期 | 回退 `x-operator-*`，标记 `trust=header` |
| 仅请求头 | 空白值被 trim 后作为身份，`trust=header` |
| 无任何身份 | `trust=none`，不产生 operatorId/Name |
| 非 Bearer 认证头 | `Basic` 等不解析，按 header/none 处理 |
| Bearer 大小写 | `bearer`/`BEARER` 均可解析 |

> 说明：`jose@6` 为 ESM-only，Jest（CJS）无法直接加载，故用例 mock `@/lib/security/jwt` 的 `verifyToken`；真实签名/验签由运行时链路（登录 → 导出）与类型检查保障。

**前端分页**（`__tests__/pagination.test.ts` 6 条 + `__tests__/components/data-table-pagination.test.tsx` 5 条）：

| 用例 | 关键断言 |
| --- | --- |
| 切片与总页数 | 45 行 / 20 条 → 3 页；首页 20 行，末页 5 行 |
| 页码收敛 | 99 → 末页、0/负数 → 第 1 页、小数向下取整 |
| 空与非法 pageSize | 空数据 totalPages=1；pageSize 为 0/负/NaN 时回退全量一页 |
| 不修改入参 | 返回新数组，原数组长度不变 |
| DataTable 翻页 | 下一页/末页/上一页切换页码与行数，按钮禁用态正确 |
| 兼容性 | 不传 `pageSize` 时一次渲染全部；不足一页不显示分页页脚 |

**建议补充（接入真实 API 后）**：

- 接口层：分页参数、日期时区、权限过滤、门店隔离。
- 结算层：部分结算、跨月结算、撤销后重算。
- 数据一致性：上钟记录与扣款记录外键完整性。
- 导出层：生产环境强制 `trust=jwt`（拒绝 `header` 回退）并接入真实用户表。

## 六、测试通过标准与失败判定

**通过标准**：

1. 所有 P0 用例通过。
2. 新增/修改文件 `tsc` 0 error、ESLint 0 error。
3. 单测 100% 通过。
4. 页面无 `console.error` / `pageerror`。
5. 金额勾稽与结算勾稽 100% 一致。

**失败判定**：

- 任一 P0 用例失败；
- 勾稽差额 ≠ 0；
- 页面 5xx；
- 导出文件列缺失/乱码；
- 新增类型错误或 lint error。
