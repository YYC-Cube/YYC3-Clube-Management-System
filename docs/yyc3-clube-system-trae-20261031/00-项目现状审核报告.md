## 三、深度维度分析（现状 + 问题 + 影响）

### 3.1 架构合理性

- **现状**：标准 App Router 分层，页面/组件/服务边界清晰；报表采用「页面 + 共享数据服务 + 仓储/API」模式，艺人域已接入真实 PostgreSQL。
- **已修复**：`output: 'export'` 与 API Route/proxy 互斥；现已改为 `output: 'standalone'`，构建通过（154/154 页面）。
- **Next.js 16 同步**：Turbopack 成为默认构建器；`middleware.ts` 迁移为 `proxy.ts`；动态路由 `params` 全部改为 `await params`；`viewport/themeColor` 迁至 `Viewport` 导出。
- **质量门禁**：移除 `ignoreBuildErrors` / `ignoreDuringBuilds`，构建阶段强制执行 TypeScript 检查。
- **影响**：生产构建与部署链路已恢复，架构与 Next 16 约定一致。

### 3.2 代码质量

- **现状**：`tsc --noEmit` **0 错误**；构建阶段 TypeScript 检查 **0 错误**；ESLint **0 error**（388 个既有 `any` warning）。
- **已修复**：会员表单/页面与 `Member` 模型对齐（`cardNo`、嵌套 balance/points、gender/address/remark）；`FilterBar` 增加受控搜索/筛选值/按钮文案；`DataTable` 增加 `loading`；开房套餐页改用组件契约；清理 138 个文件的无效 React 导入；移除 10 处无效 `@ts-ignore`。
- **影响**：TypeScript 门禁已恢复，后续类型回归会在构建阶段直接暴露。

### 3.4 性能风险

- **现状**：Next 16 Turbopack 编译 1.6s，类型检查 7.2s，154/154 页面，生产构建 0 warning。
- **万级实测**：10000 上下钟 + 5000 扣款下，4 个查询接口与 2 个导出端点 P95 12.8–73.5ms、0 错误（阈值 500ms），证据见 `attachments/artist-report-bench.json`。
- **问题**：`DataTable` 一次性渲染全部行、无分页/虚拟化；报表页面仍为一次性拉取（页面侧 ≤2000 条）。API 已具备服务端分页，前端分页 UI 待接入。
- **影响**：真实超万级数据进入页面时首屏与内存压力上升；服务端查询已无瓶颈。
