# 🧱 艺人报表数据模型与接口建议

> 目标：把当前前端 Mock 报表平滑替换为真实数据，保持现有聚合口径不变。
>
> **已落地脚本**：[`scripts/migrations/20261031_artist_domain.pg.sql`](../../scripts/migrations/20261031_artist_domain.pg.sql)（PostgreSQL，与 `lib/db/pg.ts` 一致，可直接执行）。
> 下文 MySQL DDL 仅保留为历史参考；实际接入以 PG 脚本为准。

## 一、领域模型

```
artist（艺人）
  └─ artist_clock_record（上下钟记录）
        ├─ artist_fee_deduction（台费扣款）
        └─ artist_fee_settlement（台费结算）
```

**核心口径**：

- 上钟记录：一次服务=一条记录；`clock_out_at IS NULL` 表示「服务中」。
- 台费：以分为单位存储（`BIGINT`）或用 `DECIMAL(10,2)`；禁止浮点。
- 扣款：可撤销；统计时排除 `status = 'revoked'`。
- 实收 = 台费 - 有效扣款。
- 应结 = 已结 + 待结；结算进度 = 已结 / 应结。

## 二、MySQL DDL 建议（历史参考）

```sql
-- 艺人档案
CREATE TABLE artist (
  id            BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
  artist_no     VARCHAR(32)  NOT NULL UNIQUE COMMENT '艺人编号',
  name          VARCHAR(64)  NOT NULL,
  level         VARCHAR(16)  NOT NULL COMMENT '首席/金牌/银牌/铜牌',
  store_id      BIGINT UNSIGNED NOT NULL,
  phone         VARCHAR(32)  NULL,
  status        VARCHAR(16)  NOT NULL DEFAULT 'active' COMMENT 'active/left',
  joined_at     DATE         NULL,
  created_at    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  KEY idx_artist_store (store_id, status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 上下钟记录
CREATE TABLE artist_clock_record (
  id                BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
  record_no         VARCHAR(32)  NOT NULL UNIQUE COMMENT '上钟单号',
  artist_id         BIGINT UNSIGNED NOT NULL,
  store_id          BIGINT UNSIGNED NOT NULL,
  room_no           VARCHAR(32)  NOT NULL,
  guest_name        VARCHAR(64)  NULL,
  clock_in_at       DATETIME     NOT NULL,
  clock_out_at      DATETIME     NULL,
  duration_minutes  INT UNSIGNED NOT NULL DEFAULT 0 COMMENT '服务端按实际时间计算',
  stage_fee         DECIMAL(10,2) NOT NULL DEFAULT 0.00,
  status            VARCHAR(16)  NOT NULL DEFAULT 'serving' COMMENT 'serving/unsettled/settled',
  operator_id       BIGINT UNSIGNED NULL,
  created_at        DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at        DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  KEY idx_clock_store_time (store_id, clock_in_at),
  KEY idx_clock_artist_time (artist_id, clock_in_at),
  KEY idx_clock_status (status),
  CONSTRAINT fk_clock_artist FOREIGN KEY (artist_id) REFERENCES artist(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 台费扣款
CREATE TABLE artist_fee_deduction (
  id                BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
  deduction_no      VARCHAR(32)  NOT NULL UNIQUE,
  clock_record_id   BIGINT UNSIGNED NOT NULL,
  artist_id         BIGINT UNSIGNED NOT NULL,
  type              VARCHAR(32)  NOT NULL COMMENT 'late/early_leave/absent/complaint/violation/equipment/other',
  amount            DECIMAL(10,2) NOT NULL,
  reason            VARCHAR(255) NOT NULL,
  status            VARCHAR(16)  NOT NULL DEFAULT 'pending' COMMENT 'pending/confirmed/revoked',
  operator_id       BIGINT UNSIGNED NULL,
  approved_by       BIGINT UNSIGNED NULL,
  approved_at       DATETIME     NULL,
  revoked_at        DATETIME     NULL,
  created_at        DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  KEY idx_deduction_record (clock_record_id),
  KEY idx_deduction_artist_time (artist_id, created_at),
  KEY idx_deduction_status (status),
  CONSTRAINT fk_deduction_clock FOREIGN KEY (clock_record_id) REFERENCES artist_clock_record(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 台费结算单（按艺人+周期）
CREATE TABLE artist_fee_settlement (
  id                BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
  settlement_no     VARCHAR(32)  NOT NULL UNIQUE,
  artist_id         BIGINT UNSIGNED NOT NULL,
  period_start      DATE         NOT NULL,
  period_end        DATE         NOT NULL,
  stage_fee_total   DECIMAL(10,2) NOT NULL DEFAULT 0.00,
  deduction_total   DECIMAL(10,2) NOT NULL DEFAULT 0.00,
  net_fee           DECIMAL(10,2) NOT NULL DEFAULT 0.00,
  settled_fee       DECIMAL(10,2) NOT NULL DEFAULT 0.00,
  status            VARCHAR(16)  NOT NULL DEFAULT 'pending' COMMENT 'pending/partial/settled',
  settled_at        DATETIME     NULL,
  created_at        DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY uk_settlement_artist_period (artist_id, period_start, period_end)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

> 若使用 PostgreSQL：`BIGSERIAL`、`NUMERIC(10,2)`、`TIMESTAMPTZ`；其余结构等价。

  "success": true,

### 3.2 已实现：服务端导出接口（2026-10-31）

```
POST /api/reports/artist/export
Content-Type: application/json

{
  "reportType": "clock-detail" | "clock-summary" | "fee-deduction" | "fee-summary",
  "filter": { "from": "YYYY-MM-DD", "to": "YYYY-MM-DD", "store": "...", "artistId": "...",
              "status": "...", "type": "...", "search": "..." }
}
```

| 项 | 约定 |
| --- | --- |
| 响应体 | `text/csv; charset=utf-8`，首字节 UTF-8 BOM（Excel 中文直开） |
| 文件名 | `Content-Disposition` 同时给 `filename=` 与 `filename*=UTF-8''...`，形如 `艺人上下钟明细_2026-10-31.csv` |
| 行数标记 | 响应头 `X-Export-Row-Count`（筛选总行数，与数据行一致） |
| 数据来源 | 响应头 `X-Artist-Data-Source: db \| mock` |
| 行数上限 | `MAX_EXPORT_ROWS = 50000`；超限 HTTP 400，提示实际行数与上限，且不落审计 |
| 审计 | 成功导出后写入 `artist_report_export_audit`；审计失败仅告警，不阻断导出 |
| 操作人 | 优先校验 `Authorization: Bearer <JWT>`（登录签发 HS256，含 userId/role/storeId/name），标记 `trust=jwt`；无有效令牌时回退 `x-operator-id`/`x-operator-name` 请求头并标记 `trust=header`（可伪造）；均无则 `none` |
| 可信标记 | 响应头 `X-Operator-Trust: jwt \| header \| none`；非 `jwt` 时服务端输出告警，便于审计追溯 |
| 客户端回退 | 页面优先服务端导出；接口失败回退本地 CSV（`fallback`），无数据返回 `skipped` |

契约单一来源：[`lib/services/artist-report-export.ts`](../../lib/services/artist-report-export.ts)（类型白名单、列定义、上限、文件名、筛选序列化）；运行时入口 [`app/api/reports/artist/export/route.ts`](../../app/api/reports/artist/export/route.ts)。

### 3.3 聚合口径（PostgreSQL 实现）

`lib/db/repositories/artist-report-repository.ts` 已实现与迁移脚本一致的聚合：

```sql
SELECT a.id,
       COUNT(*)                                  AS clock_count,
       SUM(r.duration_minutes)                   AS total_minutes,
       SUM(r.stage_fee)                          AS total_stage_fee,
       COALESCE(SUM(d.deduction), 0)             AS total_deduction,
       SUM(r.stage_fee - COALESCE(d.deduction, 0)) AS net_fee
  FROM artist_clock_record r
  JOIN artist a ON a.id = r.artist_id
  LEFT JOIN (
    SELECT clock_record_id, SUM(amount) AS deduction
      FROM artist_fee_deduction
     WHERE status <> 'revoked'
     GROUP BY clock_record_id
  ) d ON d.clock_record_id = r.id
 WHERE r.clock_in_at >= ($1::date::timestamp AT TIME ZONE 'Asia/Shanghai')
   AND r.clock_in_at <  (($2::date + 1)::timestamp AT TIME ZONE 'Asia/Shanghai')
 GROUP BY a.id
 ORDER BY net_fee DESC;
```

- 日期按 `Asia/Shanghai` 解释，`to` 为闭区间（自动 +1 天）；
- 明细指标与汇总指标使用同一有效扣款子查询，保证口径一致；
- 服务中记录计入上钟次数，不计入平均时长。

## 四、业务规则与边界

| 规则 | 说明 |
| --- | --- |
| 时区 | 统一 `Asia/Shanghai`；API 接收 `YYYY-MM-DD` 并按门店时区解释 |
| 跨零点 | `duration_minutes = TIMESTAMPDIFF(MINUTE, clock_in_at, clock_out_at)`，允许跨天 |
| 撤销扣款 | `status='revoked'` 永久排除统计，但保留审计记录 |
| 部分结算 | 结算单支持 `partial`，报表「待结」= 应结 - 已结累计 |
| 权限 | 门店隔离；财务/店长可看金额，普通运营隐藏手机号 |
| 导出 | 服务端导出限制 5 万行，成功/超限均记录审计；超限不生成文件 |
| 服务中 | 不计入平均时长；KPI 可单列「当前服务中」 |
| 压测基线 | 10000 上下钟 + 5000 扣款：P95 明细 44.8ms / 汇总 20.5ms / 扣款 73.5ms / 流水 24.5ms / 导出 12.8–47.3ms |

## 五、替换前端 Mock 的落地步骤

1. ✅ 建表 + 迁移，导入艺人档案（`artist`）。
2. ✅ 实现 4 个查询接口（分页 + 聚合），返回结构与 `ArtistClockRecord` 对齐。
3. ✅ 实现仓储层 `lib/db/repositories/artist-report-repository.ts` 与数据源编排 `lib/services/artist-report-data.ts`。
4. ✅ 页面通过 `hooks/use-artist-report-records.ts` 读取接口；`artist-report.ts` 保留过滤/聚合与 Mock 回退。
5. ✅ 服务端导出 + 审计 + 5 万行上限已实现；页面优先服务端导出，失败回退本地 CSV。
6. ✅ 导出操作人接入登录会话身份（HS256 JWT → `trust=jwt`），过渡期保留请求头回退并标记 `header`。
7. ⬜ 增加权限测试与门店越权测试；生产环境禁用 `header` 回退（接入真实用户表）；完成 Excel 实机验收。

**回退策略**：

- `ARTIST_REPORT_DATA_SOURCE=auto`（默认）：数据库异常/表未建时回退 Mock，页面不空白；
- `db`：强制真实库，异常返回 500；
- `mock`：纯演示数据，适合离线演示与前端联调。
